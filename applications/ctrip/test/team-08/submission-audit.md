# Team 08 submission eligibility audit

The course requires requirement compliance, distinct coverage, and a reproducible discrepancy with the reference system. Each case has an executable Playwright script, named baseline comparisons, and a record of the expected and observed behavior. The scripts use public UI flows with the course clock. Application and baseline files are outside this change. [Course submission criteria](../../../../README.md) · [Ctrip requirements](../../requirements/requirements.yaml)

The team shortlist contains ten candidates, including three with white-box designs. Each candidate has its own run command. Eligibility uses the supplied requirements and baseline scenarios as expected-behavior evidence. Independent execution against a separate reference system remains unverified.

The shortlisted cases check distinct outcomes. The saved-information cases add invoice identity uniqueness and correct address selection during overlapping reads. The earlier duplicate-booking case checks repeated activation of a single in-flight submission. The invoice case completes the first save and reloads before starting the second.

## Local verification

All ten shortlisted cases reproduced individually in Chromium on a fresh local course instance. The seven shortlisted black-box write-ups embed screenshot sequences from `assets/`. The three white-box write-ups link their source paths and executable Playwright evidence. The team index lists both members, the design method for every case, dependencies, independent run commands, and the PR title format. Each case document includes the expected and observed output, reproduction steps, and closest baseline tests.

The verified changes are local to Team 08. Finishing the course submission requires committing the selected cases and their evidence, pushing the branch, and opening a PR against upstream `main` with links to the selected write-ups.
